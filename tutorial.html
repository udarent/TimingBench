Hitchhiker's Guide to WaveJSON

Following WaveDrom's tutorial order: the code blocks are plain WaveJSON, exactly as in the original tutorial — the diagrams below each one are live, editable embed blocks rendered by the same editor, not images.

WaveJSON is a format that describes digital timing diagrams. A document is a plain object whose signal array holds the wave lanes; each character in a lane's wave string is one time period and . repeats the previous state.
Click any diagram below to edit it. Change a cell, drag on the canvas, or use the segmented control in the top bar to switch between diagram, code, and both (the block's own source, pretty-printed). Esc returns to read-only.

Step 1. The signal

A lane has two required fields: name and wave. Each wave character is one period; . repeats the previous state.

{ signal: [{ name: "Alfa", wave: "01.zx=ud.23.456789" }] }

Click a cell, then pick a character; 0 1 x z u d p P n N h l H L = 2–9 are all supported.

Step 2. Clock

A clock is a special signal that changes twice per period, with positive or negative polarity and an optional marker on the working edge. Clock blocks can be mixed with other states for gating.

{ signal: [
  { name: "pclk", wave: "p......." },
  { name: "Pclk", wave: "P......." },
  { name: "nclk", wave: "n......." },
  { name: "Nclk", wave: "N......." },
  {},
  { name: "clk0", wave: "phnlPHNL" },
  { name: "clk1", wave: "xhlhLHl." },
  { name: "clk2", wave: "hpHplnLn" },
  { name: "clk3", wave: "nhNhplPl" },
  { name: "clk4", wave: "xlh.L.Hx" }
] }

Step 3. Putting it together

A typical diagram mixes a clock with wires and multi-bit signals. Multi-bit (bus) lanes take their labels from the data array.

{ signal: [
  { name: "clk",  wave: "P......" },
  { name: "bus",  wave: "x.==.=x", data: ["head", "body", "tail", "data"] },
  { name: "wire", wave: "0.1..0." }
] }

Step 4. Spacers and gaps

{} inserts a spacer row; | draws a phase line (a gap) at that period.

{ signal: [
  { name: "clk",         wave: "p.....|..." },
  { name: "Data",        wave: "x.345x|=.x", data: ["head", "body", "tail", "data"] },
  { name: "Request",     wave: "0.1..0|1.0" },
  {},
  { name: "Acknowledge", wave: "1.....|01." }
] }

Add a spacer from a row's action bar; toggle a gap from a column's action bar.

Step 5. Groups

Lanes can be united in named groups written as arrays: the first entry is the group's name and groups can be nested.

{ signal: [
  { name: "clk", wave: "p..Pp..P" },
  ["Master",
    ["ctrl",
      { name: "write", wave: "01.0...." },
      { name: "read",  wave: "0...1..0" }
    ],
    { name: "addr",  wave: "x3.x4..x", data: "A1 A2" },
    { name: "wdata", wave: "x3.x....", data: "D1" }
  ],
  {},
  ["Slave",
    ["ctrl",
      { name: "ack", wave: "x01x0.1x" }
    ],
    { name: "rdata", wave: "x.....4x", data: "Q2" }
  ]
] }

You can build groups right on the canvas: select a row (Shift-click another row name to take a range), then use group rows in the action bar and type a name. What you type is the whole path — one segment per level: bus is a top-level group, a/b nests it one level down, and an empty path means "not in any group". To add a level, append a segment (a/b → a/b/c); to drop one, delete the last segment — the path is the whole story. Click the brace of the level you want to change, and the whole subtree follows. Moving a row out of a group simply drops it out, so a group never splits into two braces with the same name.

Step 6. Period and phase

period and phase adjust a lane: period scales a character's width, phase shifts it by a fraction of a period. A DDR read transfer is the classic example.

{ signal: [
  { name: "CK",   wave: "P.......",                                              period: 2 },
  { name: "CMD",  wave: "x.3x=x4x=x=x=x=x", data: "RAS NOP CAS NOP NOP NOP NOP", phase: 0.5 },
  { name: "ADDR", wave: "x.=x..=x........", data: "ROW COL",                      phase: 0.5 },
  { name: "DQS",  wave: "z.......0.1010z." },
  { name: "DQ",   wave: "z.........5555z.", data: "D0 D1 D2 D3" }
] }

Both fields are applied to the drawing and can be edited in place. Click φ next to a row name to start editing that row's phase — then simply drag the wave itself sideways: it follows your finger, one cell is one period. There is no slider to find. The arrow keys nudge by 0.05, 0 resets, Esc cancels and Enter accepts; a plain tap selects the cell and leaves the mode. Dragging right always moves the wave right. Phase shifts the lane left by exactly that many periods — it is continuous, so 0.1 and 0.2 differ by a tenth of a cell (WaveDrom shifts it the same way but throws away the leading half bricks; we keep them and clip at the wave origin). T is the period: it stretches every character of that row and is edited as a number. The numbered ruler above still counts reference periods, so a period: 2 row spans two ruler columns per character. On touch the same two entries exist: select the row and tap the phase icon in the context bar to grab the wave, or tap the φ / T glyph beside the row name for the numeric box — since 0.17.0 those glyphs carry an enlarged hit rect, so they are tappable on a phone too. What a phone cannot give you at rest is fine resolution: the whole picture is scaled down to fit the screen, so a tenth of a period is only a few pixels wide — pinch with two fingers to zoom in (up to 4×, the point between your fingers stays put) and it becomes readable, or use the numeric box for exact values. On a desktop the same zoom is Ctrl/⌘ + wheel (a trackpad pinch arrives as exactly that). Pinching back down restores the fit-to-screen view, and keeps going until the whole diagram fits the viewport. A second finger always switches the gesture to pan / zoom (and undoes the phase nudge of that same gesture).

Step 7. The config, head and foot

config controls rendering (for example hscale). head and foot add text, ticks, tocks and an every interval above and below the diagram.

{ signal: [
  { name: "clk",     wave: "p...." },
  { name: "Data",    wave: "x345x", data: ["head", "body", "tail"] },
  { name: "Request", wave: "01..0" }
],
  config: { hscale: 1 }
}
{ signal: [
  { name: "clk",     wave: "p...." },
  { name: "Data",    wave: "x345x", data: "a b c" },
  { name: "Request", wave: "01..0" }
],
  head: { text: "WaveDrom example", tick: 0, every: 2 },
  foot: { text: "Figure 100", tock: 9 }
}

config.hscale is applied for real: it widens the whole time axis (cell width × hscale, capped at 8) while row height and font size stay put — try hscale: 3 in the editor. It is a source-only field: there is no control on the canvas for config, so you change it in the text and the drawing follows (that direction works). head and foot go one step further: they stay in your source and survive every edit untouched, but their titles and tick / tock rulers are not drawn yet — so there is nothing on the canvas to click and nothing to see.

Step 8. Arrows

An edge connects two node markers. The body selects the shape — ~ curves, - / | / + are sharp — and < / > put arrowheads at the start / end. The order of the sharp characters is the order of the segments: a-|>b runs horizontally first and then drops, a|->b drops first and then runs. No arrowhead unless you ask for one: a~b is a plain curve.

Splines:     ~   -~   ~-   <~>  <-~>  ~>   -~>  ~->
Sharp lines: -   -|   -|-  <->  <-|>  <-|->  ->  -|>  -|->  |->  +
{ signal: [
  { name: "A", wave: "01........0....", node: ".a........j" },
  { name: "B", wave: "0.1.......0.1..", node: "..b.......i" },
  { name: "C", wave: "0..1....0...1..", node: "...c....h.." },
  { name: "D", wave: "0...1..0.....1.", node: "....d..g..." },
  { name: "E", wave: "0....10.......1", node: ".....ef...." }
],
  edge: ["a~b t1", "c-~a t2", "c-~>d time 3", "d~-e", "e~>f", "f->g", "g-~>h", "h~>i some text", "h~->j"]
}

Double-click an arc to edit its shape or label.

Step 9. Some code

WaveDrom's tutorial ends with a JavaScript snippet that builds a document programmatically. TimingBench reads WaveJSON, not JavaScript, so this one stays a code sample: run it where you like and paste the object it returns into the editor.

(function (bits, ticks) {
  var i, t, gray, state, data = [], arr = [];
  for (i = 0; i < bits; i++) {
    arr.push({ name: i + '', wave: '' });
    state = 1;
    for (t = 0; t < ticks; t++) {
      data.push(t + '');
      gray = (((t >> 1) ^ t) >> i) & 1;
      arr[i].wave += (gray === state) ? '.' : gray + '';
      state = gray;
    }
  }
  arr.unshift('gray');
  return { signal: [ { name: 'bin', wave: '='.repeat(ticks), data: data }, arr ] };
})(5, 16)

Shown as a reference for generating WaveJSON — the editor itself never runs it.
