Hitchhiker's Guide to WaveJSON

Following WaveDrom's tutorial order: the code blocks are plain WaveJSON, exactly as in the original tutorial — the diagrams below each one are live, editable embed blocks rendered by the same editor, not images.

WaveJSON is a format that describes digital timing diagrams. A document is a plain object whose signal array holds the wave lanes; each character in a lane's wave string is one time period and . repeats the previous state.
Click any diagram below to edit it. Change a cell, drag on the canvas, or open the full editor for the source panel. Esc returns to read-only.

Step 1. The signal done

A lane has two required fields: name and wave. Each wave character is one period; . repeats the previous state.

{ signal: [{ name: "Alfa", wave: "01.zx=ud.23.456789" }] }

Click a cell, then pick a character; 0 1 x z u d p P n N h l H L = 2–9 are all supported.

Step 2. Clock done

A clock is a special signal that changes twice per period, with positive or negative polarity and an optional marker on the working edge. Clock blocks can be mixed with other states for gating.

{ signal: [
  { name: "pclk", wave: "p......." },
  { name: "Pclk", wave: "P......." },
  { name: "nclk", wave: "n......." },
  { name: "Nclk", wave: "N......." },
  {},
  { name: "clk0", wave: "phnlPHNL" },
  { name: "clk1", wave: "xhlhLHl." },
  { name: "clk2", wave: "hpHplnLn" },
  { name: "clk3", wave: "nhNhplPl" },
  { name: "clk4", wave: "xlh.L.Hx" }
] }

Step 3. Putting it together done

A typical diagram mixes a clock with wires and multi-bit signals. Multi-bit (bus) lanes take their labels from the data array.

{ signal: [
  { name: "clk",  wave: "P......" },
  { name: "bus",  wave: "x.==.=x", data: ["head", "body", "tail", "data"] },
  { name: "wire", wave: "0.1..0." }
] }

Step 4. Spacers and gaps done

{} inserts a spacer row; | draws a phase line (a gap) at that period.

{ signal: [
  { name: "clk",         wave: "p.....|..." },
  { name: "Data",        wave: "x.345x|=.x", data: ["head", "body", "tail", "data"] },
  { name: "Request",     wave: "0.1..0|1.0" },
  {},
  { name: "Acknowledge", wave: "1.....|01." }
] }

Add a spacer from a row's action bar; toggle a gap from a column's action bar.

Step 5. Groups done

Lanes can be united in named groups written as arrays: the first entry is the group's name and groups can be nested.

{ signal: [
  { name: "clk", wave: "p..Pp..P" },
  ["Master",
    ["ctrl",
      { name: "write", wave: "01.0...." },
      { name: "read",  wave: "0...1..0" }
    ],
    { name: "addr",  wave: "x3.x4..x", data: "A1 A2" },
    { name: "wdata", wave: "x3.x....", data: "D1" }
  ],
  {},
  ["Slave",
    ["ctrl",
      { name: "ack", wave: "x01x0.1x" }
    ],
    { name: "rdata", wave: "x.....4x", data: "Q2" }
  ]
] }

Click the [group] label after a row name to rename it; use / to nest, clear it to ungroup.

Step 6. Period and phase pending

period and phase adjust a lane: period scales a character's width, phase shifts it by a fraction of a period. A DDR read transfer is the classic example.

{ signal: [
  { name: "CK",   wave: "P.......",                                              period: 2 },
  { name: "CMD",  wave: "x.3x=x4x=x=x=x=x", data: "RAS NOP CAS NOP NOP NOP NOP", phase: 0.5 },
  { name: "ADDR", wave: "x.=x..=x........", data: "ROW COL",                      phase: 0.5 },
  { name: "DQS",  wave: "z.......0.1010z." },
  { name: "DQ",   wave: "z.........5555z.", data: "D0 D1 D2 D3" }
] }

Pending: period / phase are parsed, editable and round-tripped, but not yet applied to the drawing.

Step 7. The config, head and foot pending

config controls rendering (for example hscale). head and foot add text, ticks, tocks and an every interval above and below the diagram.

{ signal: [
  { name: "clk",     wave: "p...." },
  { name: "Data",    wave: "x345x", data: ["head", "body", "tail"] },
  { name: "Request", wave: "01..0" }
],
  config: { hscale: 1 }
}
{ signal: [
  { name: "clk",     wave: "p...." },
  { name: "Data",    wave: "x345x", data: "a b c" },
  { name: "Request", wave: "01..0" }
],
  head: { text: "WaveDrom example", tick: 0, every: 2 },
  foot: { text: "Figure 100", tock: 9 }
}

Pending: config, head and foot are kept verbatim and round-trip losslessly, but their visual effects (hscale, titles, ticks / tocks) are not drawn yet.

Step 8. Arrows done

An edge connects two node markers. The body selects the shape — ~ curves, - / | / + are sharp — and < / > put arrowheads at the start / end.

Splines:     ~   -~   ~-   <~>  <-~>  ~>   -~>  ~->
Sharp lines: -   -|   -|-  <->  <-|>  <-|->  ->  -|>  -|->  |->  +
{ signal: [
  { name: "A", wave: "01........0....", node: ".a........j" },
  { name: "B", wave: "0.1.......0.1..", node: "..b.......i" },
  { name: "C", wave: "0..1....0...1..", node: "...c....h.." },
  { name: "D", wave: "0...1..0.....1.", node: "....d..g..." },
  { name: "E", wave: "0....10.......1", node: ".....ef...." }
],
  edge: ["a~b t1", "c-~a t2", "c-~>d time 3", "d~-e", "e~>f", "f->g", "g-~>h", "h~>i some text", "h~->j"]
}

Double-click an arc to edit its shape or label.

Step 9. Some code pending

WaveDrom's tutorial ends with a JavaScript snippet that builds a document programmatically. TimingBench does not execute arbitrary JavaScript — it parses the WaveJSON object only — so this step is pending: paste the object the code returns into the editor instead.

(function (bits, ticks) {
  var i, t, gray, state, data = [], arr = [];
  for (i = 0; i < bits; i++) {
    arr.push({ name: i + '', wave: '' });
    state = 1;
    for (t = 0; t < ticks; t++) {
      data.push(t + '');
      gray = (((t >> 1) ^ t) >> i) & 1;
      arr[i].wave += (gray === state) ? '.' : gray + '';
      state = gray;
    }
  }
  arr.unshift('gray');
  return { signal: [ { name: 'bin', wave: '='.repeat(ticks), data: data }, arr ] };
})(5, 16)

Pending: not executed. Use it as a reference for generating WaveJSON, then paste the result.
